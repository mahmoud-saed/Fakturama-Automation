# Fakturama Image-to-Cash Automation

Python automation for extracting a sales order image and creating a Fakturama Order and linked Invoice. The Windows desktop adapter implements master-data resolution, line entry, totals checks, payment handling, and persisted-document verification.

## Setup

Install:

- Python 3.10 or newer
- Tesseract OCR with English language data
- Python dependencies from `requirements.txt`
- Fakturama for desktop runs, open in English in an interactive Windows session

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Tesseract must be callable as `tesseract` on `PATH`.
Verify it with `tesseract --version` and `tesseract --list-langs`; the language list must include `eng`.

## Dependencies

Runtime dependencies are intentionally small:

- `Pillow` for image loading and preprocessing
- `pywinauto` on Windows for UI Automation and native-control access
- local Tesseract OCR executable

The tests use Python's built-in `unittest`.

## Run Extraction

Submission input and output:

- Original image: [samples/order.png](samples/order.png)
- Extracted structured JSON: [samples/order.extracted.json](samples/order.extracted.json)
- Recorded extraction command, logs and result: [evidence/extraction-run.txt](evidence/extraction-run.txt)

The standalone JSON matches the recorded successful CLI output, including its `status` and `order` fields. Dates use ISO format; monetary and other decimal values remain strings to preserve precision. It was packaged from the existing transcript, not generated by a new run.

Sample command:

```powershell
.\.venv\Scripts\python.exe -m fakturama_automation samples/order.png --log-level INFO
```

The command prints JSON to stdout and logs progress to stderr.

Successful extraction returns exit code `0` (abbreviated output):

```json
{
  "status": "valid",
  "order": {
    "external_reference": "WEB-2026-0714-A17"
  }
}
```

Manual review returns exit code `2`:

```json
{
  "status": "manual_review",
  "reason": "Source totals do not match the order items"
}
```

The parser currently targets the supplied Sales Order Input image layout. Dates are normalized to ISO format, numeric values use `Decimal`, OCR confidence must be at least `70`, and source totals are checked before any automation step is allowed.

## Run the Desktop Workflow

Use a separate, empty Fakturama test workspace for the pending uninterrupted acceptance run. Keep the existing verified workspace unchanged. Close or resolve unsaved editors before running, keep the application visible, and do not use the mouse or keyboard during automation.

The inspected sample setup uses EUR with Fakturama's Currency locale set to Germany in `File > Preferences`. Monetary entry uses the Order's formatted decimal separator. Other application languages and layouts have not been verified.

```powershell
.\.venv\Scripts\python.exe -m fakturama_automation samples/order.png --run --log-level INFO --evidence-dir evidence/acceptance-run
```

Without `--run`, the CLI only extracts and validates the image. With `--run`, it connects to exactly one running Fakturama window; it does not launch the application. Both the terminal and Fakturama must have compatible permissions to interact with the desktop.

Completion returns exit code `0` and JSON containing `status: completed`, `order_number`, `invoice_number`, and `gross_total`. A review condition returns exit code `2` and `status: manual_review`.

The adapter refuses to start with unsaved editors or Documents matching the source reference. Do not rerun the same source in the current verified workspace expecting another Order. After a failed run, inspect any saved records and open drafts before restarting: master records or a document may already have been saved. Uncertain saves are not retried automatically.

## Logging

The CLI logs:

- input image path
- OCR completion and word count
- valid extraction summary
- manual-review reason on failure
- desktop workflow stages, menu actions, and verified document identifiers

Use `--log-level DEBUG`, `INFO`, `WARNING`, or `ERROR` to adjust verbosity.

Desktop-stage logs are appended to `run.log` in the selected evidence directory. Extraction logs go to stderr before that file handler is attached. Existing staged-run and final readback logs are in [evidence/live-run/run.log](evidence/live-run/run.log).

## Failure Screenshots

`fakturama_automation.ui.FakturamaUI` writes a screenshot when a UI action fails because a control is missing, disabled, ambiguous, or unreadable. The desktop adapter chooses the evidence directory when it constructs `FakturamaUI`.

Screenshots are named `<step>_<timestamp>.png`. The error and log include the path. The CLI also attempts `manual-review.png` for other desktop exceptions. If capture fails, the original action error is preserved and the capture failure is logged. Actual live failure examples are annotated in `evidence/ANNOTATED_RUN.md`. The UI tests use placeholder bytes to test file creation; those files are not submission screenshots.

The desktop adapter uses named controls and label relationships where available. Custom SWT tables require visual grounding from the current capture; no saved absolute screen coordinates are used. Successful evidence capture is best effort and does not turn a completed save into an action failure.

## Workflow Modules

`fakturama_automation.master_data.open_order_and_resolve(order, desktop)` opens an Order, keeps it open, and resolves Debtor, payment method, VAT, and Product records through a `MasterDataPort`.

`fakturama_automation.order_completion.complete_and_verify_order(order, resolved, desktop)` fills selected lines, checks totals, saves once, and verifies the saved Order row through an `OrderCompletionPort`.

`fakturama_automation.invoice.create_and_verify_invoice(order, saved_order, resolved, desktop)` creates the Invoice from the saved Order follow-up action, applies payment state, saves once, and verifies both final documents through an `InvoicePort`.

The ports make the workflow testable without a live Fakturama database. `fakturama_automation.desktop.FakturamaDesktop` implements the three ports using `WindowsControls` and the inspected application controls.
